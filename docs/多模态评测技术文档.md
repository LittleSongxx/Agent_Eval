## 功能概述

### 设计目标

支持多模态AI应用的评测，覆盖图像理解的主要场景：
- **图像OCR评测**：评测文字识别准确率
- **图文匹配度评测**：评测图像描述生成质量
- **视觉问答评测**：评测图像理解和推理能力

### 技术特点

1. **复用LLM-as-Judge架构**
   - 保持与文本评测一致的评测流程
   - 替换为视觉语言模型（qwen-vl-plus）
   - 统一的结果格式和API接口

2. **多维度评测**
   - OCR：字符准确率、词准确率、编辑距离
   - 图文匹配：内容一致性、细节准确性、完整性
   - 视觉问答：准确率、错误分类、参考答案对比

3. **完整测试覆盖**
   - 45个单元测试（19个客户端 + 26个评测器）
   - 100%测试通过率
   - Mock所有外部依赖

   ├── 得分 (score)
   ├── 评测理由 (reasoning)
   ├── 详细结果 (任务特定)
   └── Token消耗 (tokens_used)

### 2. ImageOCREvaluator (OCR评测器)

**文件**：`backend/app/core/multimodal_evaluator.py` (部分)

**功能**：
- 评测AI对图像中文字的识别准确率
- 计算字符级和词级准确率
- 计算Levenshtein编辑距离
- 生成详细的错误分析

**核心算法**：

**字符级准确率**（SequenceMatcher）：
```python
from difflib import SequenceMatcher

matcher = SequenceMatcher(None, ground_truth, predicted)
char_accuracy = matcher.ratio()  # 0.0 - 1.0
```

**编辑距离**（Levenshtein Distance）：
```python
def _levenshtein_distance(self, s1: str, s2: str) -> int:
    """动态规划计算编辑距离"""
    if len(s2) == 0:
        return len(s1)
    
    previous_row = range(len(s2) + 1)
    for i, c1 in enumerate(s1):
        current_row = [i + 1]
        for j, c2 in enumerate(s2):
            insertions = previous_row[j + 1] + 1
            deletions = current_row[j] + 1
            substitutions = previous_row[j] + (c1 != c2)
            current_row.append(min(insertions, deletions, substitutions))
        previous_row = current_row
    
    return previous_row[-1]
```

**错误分析**：
- 漏识别检测：`len(predicted) < len(ground_truth) * 0.8`
- 误识别检测：`len(predicted) > len(ground_truth) * 1.2`
- 质量分级：优秀(≥95%)、良好(≥85%)、中等(≥70%)、较差(<70%)

**示例输出**：
```python
OCREvaluationResult(
    sample_id="test-001",
    predicted_text="发票号码: 12345679",
    ground_truth_text="发票号码: 12345678",
    char_accuracy=0.9412,  # 16/17字符正确
    word_accuracy=0.8333,  # 2/3词正确
    edit_distance=1,
    reasoning="OCR识别质量：优秀。字符级准确率为94.12%，词级准确率为83.33%，编辑距离为1。主要是字符替换错误。"
)
```

### 3. ImageTextMatchEvaluator (图文匹配度评测器)

**功能**：
- 评测AI生成的描述与图像内容的一致性
- 从3个维度打分（1-5分）
- 获取图像真实内容作为参考

**评测维度**：

1. **内容一致性** (Content Consistency)
   - 描述的主要内容是否与图像一致
   - 有无明显的幻觉或虚构

2. **细节准确性** (Detail Accuracy)
   - 具体细节（颜色、位置、数量等）是否准确
   - 属性描述是否正确

3. **完整性** (Completeness)
   - 是否覆盖了图像的重要信息
   - 有无遗漏关键内容

**Prompt设计**：
```python
prompt = f"""你是一个图文匹配度评测专家。请评估以下文本描述与图像内容的匹配程度。

文本描述：
{text_description}

请从以下3个维度进行评分（1-5分）：
1. 内容一致性：描述是否与图像内容一致
2. 细节准确性：关键细节是否准确
3. 完整性：是否覆盖了重要信息

请按以下JSON格式输出（只输出JSON，不要其他内容）：
{{
  "content_consistency": <1-5分数>,
  "detail_accuracy": <1-5分数>,
  "completeness": <1-5分数>,
  "overall_score": <平均分>,
  "reasoning": "<详细评测理由，说明为什么给出这些分数>"
}}"""
```

**示例输出**：
```python
ImageTextMatchResult(
    sample_id="test-101",
    generated_description="一只橘色的猫坐在窗台上，阳光洒在它的身上",
    content_consistency=5,
    detail_accuracy=4,
    completeness=5,
    overall_score=4.7,
    reasoning="描述非常准确。内容一致性满分：猫、橘色、窗台都准确。细节准确性4分：阳光细节正确但非核心信息。完整性满分：覆盖了主要元素。",
    true_content_summary="一只橘色的猫坐在窗台上"
)
```

### 4. VisualQAEvaluator (视觉问答评测器)

**功能**：
- 评测AI对图像内容的理解和推理能力
- 判断答案正确性
- 分类错误类型
- 提供参考答案对比

**答案评估策略**（多层次匹配）：

1. **精确匹配** (score=1.0)
```python
if pred_normalized == gt_normalized:
    return True, 1.0, None, "答案完全正确"
```

2. **包含关系** (score=0.9)
```python
if gt_normalized in pred_normalized or pred_normalized in gt_normalized:
    return True, 0.9, None, "答案基本正确"
```

3. **参考答案匹配** (score=0.85)
```python
if pred_normalized == ref_normalized:
    return True, 0.85, None, "与模型参考答案一致"
```

4. **数字提取匹配** (score=0.9)
```python
pred_numbers = re.findall(r'\d+', predicted)
gt_numbers = re.findall(r'\d+', ground_truth)
if pred_numbers == gt_numbers:
    return True, 0.9, None, "关键数字正确"
```

5. **相似度匹配** (score=similarity)
```python
similarity = SequenceMatcher(None, pred, gt).ratio()
if similarity >= 0.7:
    return True, round(similarity, 2), None, "部分正确"
```

**错误类型分类**：
- `counting_error` - 计数错误（"多少"、"几"）
- `attribute_error` - 属性错误（"颜色"、"什么色"）
- `location_error` - 位置错误（"位置"、"哪里"）
- `judgment_error` - 判断错误（"是否"、"有没有"）
- `understanding_error` - 理解错误（其他）

**示例输出**：
```python
VisualQAEvaluationResult(
    sample_id="test-201",
    question="图中有几辆红色汽车？",
    predicted_answer="2辆",
    ground_truth_answer="3辆",
    is_correct=False,
    score=0.0,
    reference_answer="3辆红色汽车",
    error_type="counting_error",
    reasoning="答案错误：预测为'2辆'，标准答案为'3辆'，模型参考答案为'3辆红色汽车'。"
)
```

## 评测指标

### OCR评测指标

| 指标 | 计算方法 | 取值范围 | 说明 |
|------|---------|---------|------|
| 字符准确率 | SequenceMatcher.ratio() | 0.0 - 1.0 | 字符级别的相似度 |
| 词准确率 | 分词后的SequenceMatcher | 0.0 - 1.0 | 词级别的相似度 |
| 编辑距离 | Levenshtein Distance | 0 - ∞ | 最小编辑操作数 |

**质量等级**：
- **优秀**：字符准确率 ≥ 95%
- **良好**：字符准确率 ≥ 85%
- **中等**：字符准确率 ≥ 70%
- **较差**：字符准确率 < 70%

### 图文匹配度指标

| 维度 | 评分范围 | 说明 |
|------|---------|------|
| 内容一致性 | 1-5分 | 描述的主要内容与图像是否一致 |
| 细节准确性 | 1-5分 | 具体细节（颜色、位置等）是否准确 |
| 完整性 | 1-5分 | 是否覆盖了图像的重要信息 |
| 综合得分 | 1-5分 | 三个维度的平均分 |

### 视觉问答指标

| 指标 | 计算方法 | 取值范围 | 说明 |
|------|---------|---------|------|
| 准确率 | 正确数 / 总数 | 0.0 - 1.0 | 批量评测时统计 |
| 单样本得分 | 多层次匹配策略 | 0.0 - 1.0 | 精确匹配=1.0, 语义匹配=0.8-0.9 |

**错误类型**：
- `counting_error` - 计数类问题答错
- `attribute_error` - 属性类问题答错
- `location_error` - 位置类问题答错
- `judgment_error` - 判断类问题答错
- `understanding_error` - 其他理解错误

## 性能与成本

### Token消耗

| 组件 | Token消耗 | 说明 |
|------|----------|------|
| 图像输入 | 1000-2000 | 根据图像大小估算 |
| OCR识别 | 图像tokens + 输出tokens | 单次调用 |
| 图文匹配 | 图像tokens × 2 + 文本tokens | 两次图像理解调用 |
| 视觉问答 | 图像tokens + 问题tokens + 答案tokens | 单次调用 |

**示例成本估算**（qwen-vl-plus: ¥0.004/1k tokens）：
```
OCR单样本: ~1500 tokens = ¥0.006
图文匹配单样本: ~3500 tokens = ¥0.014
视觉问答单样本: ~1600 tokens = ¥0.0064
```

**背景**：

**方案**：
"我的方案是复用现有的LLM-as-Judge架构，但替换评测模型为视觉语言模型（qwen-vl-plus）。具体实现了三类评测：

1. **OCR准确率评测**：计算字符级和词级准确率，使用Levenshtein编辑距离量化差异，能检测漏识别、误识别等问题。

2. **图文匹配度评测**：从内容一致性、细节准确性、完整性三个维度打分（1-5分），模型会详细解释为什么给出这些分数，还会提供图像真实内容作为参考。

3. **视觉问答评测**：判断答案是否正确，使用多层次匹配策略（精确匹配、语义匹配、数字提取匹配等），并分类错误类型（计数错误、属性错误等）。"

**技术亮点**：
"技术挑战主要是：
- 多模态Prompt设计（如何让模型给出结构化的评分）
- 评测标准的定义（图像评测主观性更强）
- 成本控制（图像token消耗是文本的10-20倍）

工程上写了45个单元测试，100%通过，保证了代码质量。"

**效果**：
"可以完整评测多模态AI应用的各个环节，成本方面单样本约0.6-1.4分钱，可接受。"

### 深度追问应对

**Q1: 多模态幻觉怎么评测？**

A: "可以复用已实现的对抗验证机制。让两个VL模型（如qwen-vl和claude-vision）独立评分，如果分歧大（比如差值>0.3），标记为人工复核。

另外可以设计专门的幻觉检测样本。比如：
- 让AI描述图中不存在的物体，检测其是否会幻觉
- 提供故意混淆的问题（'图中的大象在哪里？' 但图中没有大象）
- 对比模型的描述与真实内容，标记额外添加的信息

这些方法结合起来可以量化多模态幻觉的发生率。"

**Q2: 为什么不用CLIP等Embedding模型？**

A: "CLIP更适合图文检索和相似度计算场景。它的输出是Embedding向量，可以算余弦相似度，但：
1. 缺乏可解释性：只有一个相似度分数，无法知道哪里不匹配
2. 无法给出改进建议：不能告诉用户描述哪里有问题
3. 评测维度单一：无法分维度评分

我的场景是评测AI生成内容的质量，需要detailed reasoning而不只是相似度。所以选择了qwen-vl-plus这种视觉语言模型，它可以：
1. 给出详细的评测理由（为什么给这个分）
2. 分维度评分（内容、细节、完整性）
3. 提供改进建议

当然如果只是做图文检索ranking，CLIP会更合适。"

**Q3: 成本会增加多少？怎么控制？**

A: "多模态模型的token消耗确实更大。一张图像约等效1000-2000个文本token，相比纯文本评测，成本增加约2-3倍。

具体控制方法：
1. **图像优化**：压缩到1024×1024以内，减少50%token
2. **批量推理**：使用OpenAI Batch API（如果qwen支持），节省50%
3. **结果缓存**：相同图像+任务的结果缓存，避免重复计算
4. **采样评测**：不是每个样本都评，随机采样10-20%
5. **分层路由**：简单任务用小模型（qwen-vl-turbo），复杂任务才用plus/max

根据实验，用了这些优化后，成本增加控制在1.5-2倍，可接受。"

**Q4: 如何保证评测的客观性？**

A: "多模态评测确实主观性更强。我的方案：

1. **明确的评分标准**：
   - 每个维度有具体的判断标准
   - 1-5分每个分数有明确定义
   - 给出评分示例作为参考

2. **对抗验证**：
   - 两个VL模型独立评分
   - 计算Cohen's Kappa量化一致性
   - 分歧样本标记人工复核

3. **参考答案机制**：
   - 视觉问答时模型独立回答作为参考
   - 对比AI答案与参考答案
   - 减少因模型理解差异导致的误判

4. **人工标注校准**：
   - 定期人工复核评测结果
   - 调整评测标准和Prompt
   - 跟踪一致性变化趋势

5. **多维度评分**：
   - 不是单一总分，而是分维度
   - 每个维度独立评分
   - 更细粒度，减少偶然性

这样可以将主观性控制在可接受范围，同时保持评测的可解释性。"

**Q5: 实际落地遇到的最大挑战是什么？**

A: "最大挑战是**Prompt的稳定性**。

问题：
- 让VL模型输出结构化JSON时，格式经常不稳定
- 有时会输出```json包裹，有时直接输出
- 偶尔会添加额外解释文本，破坏JSON格式

解决方案：
```python
# 1. 明确要求（在Prompt中）
'请按以下JSON格式输出（只输出JSON，不要其他内容）'

# 2. 容错解析
response = response.strip()
if response.startswith('```json'):
    response = response[7:]
if response.endswith('```'):
    response = response[:-3]
result = json.loads(response.strip())

# 3. 降低temperature
temperature=0.2  # 更确定性的输出

# 4. 失败降级
except json.JSONDecodeError:
    # 返回默认结果，避免评测中断
    return default_result
```

经过这些优化，JSON解析成功率从60%提升到95%+。剩余5%失败的会返回默认3分评价，不影响整体评测流程。"
