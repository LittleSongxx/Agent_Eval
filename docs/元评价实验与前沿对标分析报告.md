# AI 评测平台元评价实验与前沿对标分析报告

- 报告日期：2026-08-06
- 被测系统：AI Evaluation Platform（AI 评测平台，v0.1.0 + 迭代）
- 评测环境：Qwen3.7-plus（OpenAI 兼容 MaaS 网关）、ragas 0.3.7、langchain-openai 1.4.1、Python 3.11
- 报告目的：记录"评测系统自身的评测"（元评价）全部实验与真实结果；分析本项目与 RAGAS
  同台竞技的差距与对标优化方案；评估检索侧指标的测试可行性；对照 2026 年前沿评测方法
  给出成熟度评估与优化路线图。

## 一、报告背景与实验体系

### 1.1 为什么需要元评价

LLM 应用评测的三个现实问题：

1. **LLM-as-Judge 不是真值**——同一行样本，Judge 可能给出不同分数，甚至与人工判断相左；
2. **自研指标没有背书**——本平台刻意不套 RAGAS/DeepEval（避免版本锁定、支持中文业务指标），
   这意味着"分数含义"必须自己证明；
3. **分数会被"用错"**——如果指标分不出好坏，任何基于它的优化决策都是盲的。

元评价把评测系统当作被测对象，回答"这套分数我该信几分"。

### 1.2 四层实验体系

| 层次 | 回答的问题 | 实验 |
|------|-----------|------|
| 区分度（Discrimination） | 指标能分开好坏吗 | 错误注入实验（已完成） |
| 结构效度（Concurrent Validity） | 与业界框架判断一致吗 | RAGAS 对照实验（已完成） |
| 准则效度（Criterion Validity） | 与人工判断一致吗 | 人工黄金集一致性（**已实测** 2026-08-06：kappa 0.4582，见 §2.6） |
| 信度（Reliability） | 测得稳吗 | 多采样标准差（**已实测** 2026-08-06：mean_std 0.0193，见 §2.5） |
| 实用性（Pragmatics） | 用得起吗 | token 成本、延迟、失败率（平台内置） |

## 二、已完成实验与真实结果

### 2.1 区分度实验：错误注入（3 行样本）

构造方法：取种子 RAG 样本（"Python 列表与元组的区别"）为基线，注入两类典型错误：

| 指标 | 正确基线 | 幻觉注入（"元组也是可变的"） | 无关回答（聊天气） |
|------|---------|---------------------------|-------------------|
| faithfulness（忠实性） | 1.0 | **0.0** | **0.0** |
| factual_correctness（事实性） | 1.0 | **0.0** | **0.0** |
| answer_relevancy（相关性） | 1.0 | 0.1 | **0.0** |
| answer_completeness（完整性） | 1.0 | 0.1 | 0.0 |
| context_recall（检索侧） | 1.0 | 1.0（不受影响） | 0.5 |
| context_precision（检索侧） | 1.0 | 1.0（不受影响） | 1.0 |

**结论**：
- 生成侧指标对幻觉/答非所问高度敏感（1.0 → 0.0），区分度显著；
- 检索侧指标在生成侧污染下基本稳定，验证了"检索质量与生成质量解耦"的分层设计
  （这正是"检索问题"与"生成问题"可独立定位的设计意图）。

### 2.2 结构效度实验：与 RAGAS 对照（完整过程）

#### 阶段一：n=5 种子集（流程验证级）

| 指标 | 平台均值 | RAGAS 均值 | 观察 |
|------|---------|-----------|------|
| faithfulness | 0.88 | 0.56 | 绝对分差异大（见解读 ①） |
| answer_relevancy | 0.98 | 0.81 | 弱正相关 |
| context_precision | 1.0 | 0.90 | 几乎无方差 |
| context_recall | 0.63 | 0.17 | 弱正相关 |

解读 ①：RAGAS 的 faithfulness/recall 采用**原子断言级拆解**（把回答拆成一句句陈述、
逐句与上下文核对、未覆盖即扣分），平台为**整体判定**——绝对分系统性差异来自判断粒度，
不是谁对谁错。n=5 的相关系数无统计意义，仅作流程验证。

#### 阶段二：n=25 纯好样本集（暴露天花板效应）

RAG 数据集生成器基于真实业务文档（电商售后政策，10 章节）产出 25 条问答，
再补充 LLM 生成的 response 与源 chunk 上下文。结果：**双方全部 ≈1.0、零方差、
相关系数无定义**。

**发现（天花板效应）**：纯好样本集无法验证排序能力——评测集必须包含负样本，
否则任何指标都"看起来很准"。这是评测集构建方法论"正负样本分层覆盖"的实证理由。

#### 阶段三：n=25 混合集（9 正确 / 8 幻觉注入 / 8 截断不完整）——正式结果

> ⚠ **本节数字已于 2026-08-06 两次更正。** 首轮 n=25 结果因"标签泄露"（缺陷 A）
> 失效：评测集的 `generation_meta`（含 `kind: correct/hallucinated/truncated` 真值
> 标签）随 sample 下发给了裁判，等于把答案交给判卷人。此后又修掉"口径越界"
> （缺陷 B）：指标声明只看某几个字段，实际收到整行。两个缺陷详情见 §2.4，
> 下表为**两个缺陷都修完之后**的结果。

| 指标 | 平台均值 | RAGAS 均值 | Pearson | Spearman | 判定 |
|------|---------|-----------|---------|----------|------|
| faithfulness（整体判定） | 0.728 | 0.689 | 0.7347 | 0.7567 | 方向一致 |
| **faithfulness_claim（断言级）** | 0.649 | 0.702 | **0.8054** | **0.8173** | **排序高度一致** |
| answer_relevancy（整体判定） | 0.744 | 0.809 | 0.3728 | 0.2391 | 弱相关（机制差异，见第三章 + §2.4） |
| answer_relevancy_generative（生成式） | 0.913 | 0.816 | 0.5707 | 0.5446 | 中度相关 |
| context_precision | **1.000** | 1.000 | 无方差 | 无方差 | 逐行等于 RAGAS |
| context_recall | **1.000** | 1.000 | 无方差 | 无方差 | 逐行等于 RAGAS |

**结论**：

1. **断言级忠实度是本次对照的核心正面证据**：Pearson 0.8054 / Spearman 0.8173，
   落入"排序判断高度一致"区间。这是双通道设计的直接验证——RAGAS 的 faithfulness
   本身就是断言级（statement 拆解 + NLI），同机制自然更贴合。
2. **断言级对整体版的优势，在口径修正后反而变清楚了**：Pearson +0.0707、
   Spearman +0.0606。但这个数字的历史要说清楚——标签泄露时期曾显示 +0.1675 /
   +0.1227（被泄露夸大），泄露修好后一度只剩 +0.0465 / +0.0067，口径也修好后回到
   +0.0707 / +0.0606。三个数字对应三种测量条件，不是同一件事的三次测量。
   稳定不变的是分层结构：

   | 与 RAGAS 的均值偏离（越小越贴合） | correct | hallucinated | truncated |
   |---|---|---|---|
   | 整体版（两缺陷均已修） | 0.0000 | 0.1018 | 0.2250 |
   | 断言级 | 0.0000 | 0.1042 | **0.0625** |

   截断样本上断言级的偏离是整体版的 **1/3.6**——逐条拆解能识别"被截断的半句话
   构不成完整断言"，而整体判定在拿掉 `reference` 后只能依据"没编造内容 = 忠实"
   判高分。这是双通道在统计上体现独立价值的地方，而非"换个算法得到相似结果"。
3. **检索侧修复后逐行等于 RAGAS**：`context_recall` / `context_precision` 在全部
   25 行上都是 1.0，与 RAGAS 完全重合。这完成了一个此前只能推断的判断：平台检索侧
   此前那点方差（0.912 / 0.932）**全部是缺陷 B 的产物，没有一丝是检索信号**。
4. **answer_relevancy 弱相关的根因，修完才看清是两件事叠在一起**：缺陷 B（裁判看到
   `reference`，把事实错误也算进扣分）是一件，修掉后幻觉样本上的偏离从 0.284 崩到
   0.028；剩下的是真实机制差异——平台判"是否回应了问题"，会对截断给出两极分化的
   0/1；RAGAS 做反推问题 + embedding 相似度，结构上惩罚不了截断，普遍给 0.6~0.98。
   代价是相关性略降（Pearson 0.439→0.373）：**泄露此前掩盖了这个机制差异，
   让平台凑巧给出接近 RAGAS 的中间分——对的分数，错的理由**。详见 §2.4。
5. 检索侧无方差仍是实验设计边界而非能力缺陷（合成集的上下文直接取自源 chunk），
   测试可行性见第四章。

### 2.3 实验过程中的真实踩坑（环境兼容性排查链）

对照实验首次运行时暴露三个真实问题，每个都是"问题表现 → 根因定位 → 最小修复"：

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | ragas 0.4.3 导入即崩 | langchain-community 0.3+ 移除了 vertexai 模块，ragas 仍硬编码导入 | 项目内最小 shim（`backend/scripts/_shims/`），仅当对照实验运行时生效 |
| 2 | RAGAS 侧所有调用被网关拒绝（n 参数错误） | Qwen3 系模型默认开启 thinking，RAGAS 的 answer_relevancy 一次请求 n=3 被拒 | langchain ChatOpenAI 注入 `extra_body={"enable_thinking": false}` |
| 3 | answer_relevancy 全部失败 | langchain embeddings 默认走 tiktoken 长度安全路径，模型名不在白名单导致 input 损坏 | `check_embedding_ctx_length=False` 走直传路径 |

### 2.4 对照实验反过来查出的两个平台自身缺陷

对照实验最有价值的产出不是"自研指标和 RAGAS 有多像"，而是它把**平台自己的
测量误差**照了出来。两个缺陷都由同一个信号定位：平台分与 RAGAS 分在分层数据上
系统性背离。完整分析见 [meta-evaluation.md](meta-evaluation.md) §5.3。

**缺陷 A：样本真值标签泄露给裁判（已修复）**

评测集每行带 `generation_meta = {"kind": "correct|hallucinated|truncated"}`——构造
数据时留下的真值标记。下发 payload 的兜底循环把样本内所有非下划线字段无差别交给
裁判，标签因此进了 prompt：**100 个 judge prompt 里 64 个带标签**。后果是区分度和
一致性同时虚高（裁判锚定标签后，换序互评自然更"稳定"）。已修复并加了单元 +
端到端两层回归测试；关闭修复后泄露立即重现，证明测试不是空转。

首轮 n=25 结果（含"faithfulness Pearson 1.0"这类过好的数字）全部作废，§2.2
阶段三的表已是修复后重跑的干净结果。

**缺陷 B：指标口径越界——`required_fields` 不约束实际下发字段（已修复）**

`required_fields` 只用于校验字段"是否存在"，不用于裁剪 payload，于是每个内置指标
都收到全部 7 个字段：检索侧指标看得见 `response`，只判"是否回应问题"的
answer_relevancy 看得见 `reference`。

A/B 实验（`backend/scripts/ab_response_leak.py`，同批 8 条幻觉样本逐条打两次分，
唯一变量是 payload 里有没有 `response`）已证实因果：

| 指标 | 带 response | 去掉 response | RAGAS |
|------|-----------|-------------|-------|
| context_recall | 0.7875 | **1.0000** | 1.000 |
| context_precision | 0.8125 | **1.0000** | 1.000 |

去掉 `response` 后两个检索侧指标全部回到 1.0，与 RAGAS 完全一致——**平台检索侧
的那点方差不是检索质量信号，是裁判看到错误回答后把生成质量算进了检索分**。

**修复过程本身又查出一件事：原定的修复方案是错的。** 原计划"按 `required_fields`
严格裁剪 payload"，动手前先枚举了全部 17 个内置指标，发现这个方案会打断 9 个：
8 个 Agent / 多轮指标判的就是 AI 的回复，却都没把 `response` 列入
`required_fields`（那类评测跑真实接口，回复在运行时才注入，提前列为必需会让
dataset 模式整批判"字段缺失"）；`context_precision` 的判定文字明确要看参考答案，
而 `reference` 也不在它的 `required_fields` 里。

根因由此更清楚：`required_fields` 一个字段被当成两件事用——"必须存在才打分"的
校验门槛，和"裁判能看到什么"的可见范围。两个集合本就不相等。实际修复是把它们
拆开：新增独立的 `judge_fields` 口径，17 个内置指标逐个显式声明；`_sample_payload`
新增白名单模式，只下发名单内字段并整段跳过兜底循环（缺陷 A 与 B 的共同载体正是
那个兜底循环）。自定义 prompt 指标不受影响——它的可见范围由用户自己的模板决定。

修复后 n=25 实测：context_recall / context_precision **逐行等于 RAGAS**，分层总偏离
0.275 → 0.000、0.213 → 0.000。这完成了一个此前只能推断的判断：平台检索侧那点方差
百分之百是缺陷 B 的产物。生成侧要如实说明——`answer_relevancy` 幻觉样本偏离从
0.284 崩到 0.028，但与 RAGAS 的相关性略降（0.439 → 0.373），因为**泄露此前掩盖了
一个真实机制差异**：拿掉 `reference` 后裁判对截断样本给出两极判断，而 RAGAS 的
反推问题 + embedding 相似度结构上惩罚不了截断。详见
[meta-evaluation.md](meta-evaluation.md) §5.3。

这类缺陷单元测试抓不到（每个指标单独看都"正常返回分数"），只有跨框架对照才能
暴露：**两个实现同一语义的指标在同一批数据上系统性分歧，必有一方口径不对。**
这就是元评价体系存在的实证理由。

### 2.5 信度实验：重测信度实测（2026-08-06）

实验 D（meta-evaluation.md §1.2）落地：`EVAL_JUDGE_SAMPLES=5` 在 25 行混合集
（9 正确 / 8 幻觉 / 8 截断，双通道验收场景 4 个 LLM 指标 + 2 个检索侧指标）上
真实运行，每行每指标 5 次采样，共 500+ 次 Qwen Plus 调用、零失败。

| 指标 | judge_std_mean | 解读 |
|------|---------------|------|
| faithfulness | 0.029 | 稳定 |
| faithfulness_claim | 0.016 | 稳定（断言级波动更小） |
| answer_relevancy | 0.039 | 波动最大，符合"是否回应了问题"的主观判定预期 |
| answer_relevancy_generative | 0.022 | 稳定 |
| context_recall | 0.010 | 稳定 |
| context_precision | 0.000 | 零方差 |

**mean_std = 0.0193 < 0.05（稳定判据）→ 信度实测通过**。低置信对 6/150（4%），
5 个落在截断类——裁判的不确定性集中在边界样本上，低置信度标记因此有实际筛选
价值（"哪些行该人工复核"）。分层方差（采样 std 均值）随样本难度单调上升：
correct 0.000~0.027 → hallucinated 0.000~0.033 → **truncated 0.045~0.080**，
信度数字与样本难度自洽，不是笼统的"稳定"。成本 901k tokens ≈ **¥1.41**
（25 行 × 6 指标 × 5 采样）。

**重测信度（test-retest，意外收获）**：同 25 行 × 同场景 × 同配置独立跑了两轮
（任务 9 / 任务 10，各 5-sampling，相隔数小时互不可见），逐行分数 Pearson
**0.948~1.000**、平均 |分数差| 0.008~0.021、pass/fail 判定一致 24/25（唯一翻转
在幻觉类边界样本）——重测信度强于单轮内部标准差，是信度证据链的加强版。
至此四层实验体系全部有实测数据。

### 2.6 准则效度实验：人工黄金集一致性（2026-08-06）

实验 B（meta-evaluation.md §1.2 / §5.5）落地：同 25 行混合集（9 正确 / 8 幻觉 /
8 截断）由人工在报告复核页逐条标注 pass / fail，与自动判定（全部带阈值指标
≥ threshold）对比。结果：

- **一致率 18/25 = 0.72，Cohen's kappa = 0.4582**（中等一致，触发 < 0.7 的
  自动校准建议——校准闭环机制真实跑通）；
- 分歧 7 处、**6 处为"自动 pass、人工 fail"（自动过松）**：2 幻觉 + 4 截断；
  1 处反向（correct 类）。人工 pass_rate 0.36 vs 自动 0.56；
- **分层一致率随难度单调下降**：correct 89% → hallucinated 75% → truncated 50%
  ——与 2.5 信度方差分层（truncated 0.045~0.080 最高）**完全同构**：截断类既是
  裁判内部最不稳定、又是人工-自动分歧最大的区域。

**结论**：方向共识（kappa 0.46 中等一致）证明平台判定方向正确；分歧的方向性
（自动过松集中在截断/幻觉）是**可操作的校准信号**——指向判分标准对"回应不完整/
答非所问"惩罚偏弱，而非测量失效。

**校准（2026-08-06 已执行，防盲目调参的业界调研先行）**——分歧三层根因分离：
1. 截断类 faithfulness 高分 = **设计使然非 bug**（RAGAS 定义只测已说出的 claim
   是否 grounded，不测完整性；业界共识，完整性归 answer_relevancy 负责）；
2. answer_relevancy 给截断满分 = **执行漏判**（criteria 无截断可观察定义）；
   row 7 误杀 = **常识外推**（裁判脑补"完整答案还应包含…"）；
3. 幻觉类 0.5 擦线 = **阈值偏低**（DeepEval faithfulness 默认 0.8 / AR 默认 0.7）。

落地：场景 4 阈值 0.5→0.7（零成本模拟 kappa 0.4582→0.7458；0.85 更高但 0.9
误杀 correct 类，高阈值在 25 样本上是过拟合）；AR criteria 补截断可观察定义 +
防格式误杀 + 禁止常识外推。

**重跑验证结果（2026-08-07，任务 13，同 25 行 × 5 采样）**：一致率 0.72→**0.92**、
kappa 0.4582→**0.8175**（超模拟预测 0.7458）；自动过松 6→**0**；截断类 0.5→1.0、
幻觉类 0.75→1.0（校准目标类清零）；correct 类 0.889→0.778（新增 row 6 分歧）。
校准后仍分歧 2 行（row 6/7）为 correct 类整体通道误伤（AR 0.52/0.3 vs AR_gen
0.88/0.95），双通道仲裁见 meta-evaluation §5.6。
**样本量边界**：25 条 kappa 点估计 CI 宽（50 条 ±0.20），只能当方向信号。

### 3.1 机制差异对比（为什么不能直接对标）

> 调研确认（RAGAS v0.4.x 官方迁移文档与源码）：RAGAS 无 2.x 大版本，最新为 0.4.3
> （"V2 指标架构"= collections API 重构，2026-01 发布）；**answer_relevancy 的
> "反向生成问题 + embedding 余弦相似度"机制自 0.3.x 到 0.4.x 未变**——本报告的
> 机制差异分析成立，且与本项目使用的 ragas 0.3.7 行为一致。

| 指标 | 本平台实现 | RAGAS 实现 | 差异性质 |
|------|-----------|-----------|----------|
| faithfulness | 整体判定：Judge 通读 sample 后给出 0-1 分 + 理由 | 原子断言拆解：先拆回答为若干 claims，逐 claim 判定是否被上下文支持，取平均 | 判断粒度 |
| answer_relevancy | 整体判定：Judge 判断回答是否回应问题 | **生成式判定**：先让 LLM 从回答反推 N 个可能的问题（strictness=3），再与用户原问题做 embedding 余弦相似度，取最大 | **判定机制完全不同** |
| context_precision | Judge 判断检索上下文中与问题/答案相关的比例 | 分两条：LLM 逐 chunk 判定（LLMContextPrecision，需参考）；**规则版 NonLLMContextPrecision**（字符串相似度阈值 0.5 算命中） | 判定粒度 + 存在规则版 |
| context_recall | Judge 判断参考答案要点是否在检索上下文中 | 分两条：LLM claim 拆解版；**规则版 NonLLMContextRecall**（逐参考上下文与检索上下文取最大字符串相似度 ≥0.5 命中） | 判定粒度 + 存在规则版 |

**answer_relevancy 中度相关的根因**：
1. **打分信号不同**：RAGAS 打分基于"生成问题 → 语义相似度"，本质是**语义匹配信号**；
   平台打分基于"回答是否回应了问题"的**意图契合信号**。截断类样本上分歧最大——
   截断的回答可能仍"与问题相关"（RAGAS 相似度高），但平台会因内容不完整而压低分。
2. **分数分布不同**：RAGAS 通过余弦相似度天然产生连续分布；平台为 0-1 判断更易出现
   0.0/0.1/0.9/1.0 的离散簇，压缩了排序信息。
3. **调研补充**：RAGAS 的 Context Precision/Recall 家族在 v0.4.x 同时提供 LLM 版与
   **规则版**（字符串相似度，阈值 0.5）——意味着检索侧对标存在"确定性指标 ↔ 确定性指标"
   的严格同机制路径（见第四章），无需依赖 LLM 判定的一致性。

### 3.2 对标优化方案（本报告只出方案，未实施）

**目标**：让平台 answer_relevancy 与 RAGAS 在同一批样本上"同台竞技"（同机制可比），
同时保留平台整体判定的可解释性优势。

| 方案 | 做法 | 代价 | 优先级 |
|------|------|------|--------|
| A. 双通道仲裁 | 保留整体判定为最终分；同时输出"生成式通道"（同 RAGAS：LLM 反推问题 + embedding 相似度）作为参考分与一致性标记；两通道分歧大的样本标记"需人工复核" | 每行多 1 次 LLM 调用 + 1 次 embedding | P1（✅ 仲裁规则已用校准前数据验证，见 3.2a） |
| B. 严格对齐 RAGAS 机制 | 将 answer_relevancy 重构为 RAGAS 同款流程（反推问题 + 相似度） | 失去整体判定的可解释性；依赖 embedding 服务 | P2 |
| C. 逐条/逐 claim 化改造 | faithfulness/context_recall 增加"断言拆解"模式（仿 RAGAS），与整体判定并存（可切换） | 实现量大 | P1（faithfulness 已证明方向一致，可作为增强而非替换） |

**推荐组合**：A + C 并存模式——"整体判定"与"拆解判定"双引擎，场景配置可选；
对照实验时用同一引擎模式与 RAGAS 对比，得到严格同机制的相关系数。

**可量化的验收标准**（实施后）：
- 同机制模式下 answer_relevancy Spearman ≥ 0.8（n ≥ 25 混合集）；
- 双通道一致性报告：两通道分歧率 < 15% 视为稳定；
- 增加 embedding 依赖的配置说明（`LLM_EMBEDDING_MODEL`，默认 text-embedding-v3）。

### 3.2a 双通道仲裁首轮验证（2026-08-06，校准前数据 + 人工真值）

零 LLM 成本首轮分析（`scripts/dual_channel_arbitration.py --task 10`：任务 10 的
双通道分数 + 25 条人工 pass/fail 为真值，原始输出
`backend/dual_channel_arbitration_report.json`）：

- **分歧行（|AR−AR_gen| > 0.2，10 条）：用低通道 90% 一致（9/10），用高通道仅
  20%**。分歧行 9 条为人工 fail 且低通道 fail（截断/幻觉类）；唯一低通道错误是
  row 7（外部知识污染误杀：AR=0.36 fail，人工 pass，AR_gen=0.95 正确）；
- **min(两通道) 组合最优**（阈值 0.7）：一致率 0.68 / kappa 0.3939，优于整体
  通道（0.60 / 0.2733）与生成式通道（0.48 / 0.1425）；
- 机制解读：整体通道对截断/答非所问敏感但会被污染误伤；生成式通道温和（截断
  也给高分，与 RAGAS 同机制）。**取低通道 = 两机制取保守侧，恰好消掉两边的
  过松**；仅剩的误杀（row 7 类）是"外部知识污染"边界案例，可走人工复核标记；
- 边界：任务 10 是校准前数据（旧 criteria + 阈值 0.5 政策），kappa 绝对值偏低
  属预期；校准后（任务 12）完成后重跑同脚本做前后对比，是 3.2 方案 A 的
  落地验证。

## 四、检索侧指标（Recall / MRR / HitRate@K）的测试可行性

### 4.1 为什么目前没有测（能力边界？）

不是能力缺失——平台已实现 `HitRate@K`、`MRR`、`context_precision`、`context_recall`
等检索侧指标（确定性指标零 LLM 成本），且前端/API 全链路可用。**没测的原因是实验设计
边界**：

1. **黄金集要求**：`HitRate@K` / `MRR` 需要 `retrieved_context_ids`（系统实际检索到的
   文档 ID）与 `reference_context_ids`（人工标注的期望命中文档 ID）。合成数据集的
   `retrieved_contexts` 直接取自源 chunk（= 完美检索），检索 ID 全命中 → 满分无方差；
2. **真实检索链路缺失**：对照实验没有接入一个真实的检索引擎（BM25/向量库），
   `retrieved_contexts` 不是"检索出来的"，是"贴上去的"。

### 4.2 实测：BM25 端到端检索实验（2026-08-06）

#### 4.2.1 第一版实验是错的：闭式构造（发现并废弃）

最初方案是"噪声注入"：把 `noise_ids + reference_ids` 直接拼成检索结果。动手前先
做了一次数值验证，发现这套构造是**同义反复**：金标恒定排在第 n+1 位，于是
MRR ≡ 1/(n+1)、HitRate@5 ≡ (n < 5)——与数据集内容、与检索器质量、与 chunk 文本
全部无关。换一份完全不相干的数据也是同一串数字，把它当"指标随噪声单调下降 ⇒
有区分度"的证据是循环论证。原脚本废弃，改为真实检索。

#### 4.2.2 重写：真实 BM25 检索

- 检索器：项目自带零依赖中文 BM25（`scripts/bm25_mock_retriever.py`，
  字符 bigram 分词，k1=1.5、b=0.75）；
- 知识库：25 条查询的 `reference_context_ids` 引用的 6 个 chunk（job 2，每章一个）；
- 干扰项两类：**无关语料** 26 段（`_fixtures/distractor_corpus.md`，手机/咖啡/编程/
  旅行等，与售后政策零词汇重叠——易）；**同域难负例** 10 段
  （`_fixtures/hard_negatives.md`，虚构"优选商城"的售后政策，同主题同术语不同数字——
  难）；
- 检索结果唯一来源是 BM25 排序（`index.search_with_ids`），脚本任何位置不把
  `reference_context_ids` 拼进结果——由 `tests/test_retrieval_experiment.py::`
  `test_ranking_is_data_dependent` 守门：把金标正文换成无关文本后 H@1 必须归零，
  同义反复的实现过不了这条。

#### 4.2.3 结果（25 条互异查询，每条 1 个金标 ID）

| 场景 | 库 | H@1 | H@3 | H@5 | MRR |
|------|----|-----|-----|-----|-----|
| 纯知识库（无干扰） | 6 | 1.000 | 1.000 | 1.000 | 1.000 |
| 无关干扰 ×5 | 11 | 1.000 | 1.000 | 1.000 | 1.000 |
| 无关干扰 ×10 | 16 | 0.960 | 1.000 | 1.000 | 0.980 |
| 无关干扰 ×20 | 26 | 0.960 | 1.000 | 1.000 | 0.980 |
| 无关干扰 ×全部 | 32 | 0.960 | 1.000 | 1.000 | 0.980 |
| 同域难负例 ×3 | 9 | 0.960 | 1.000 | 1.000 | 0.980 |
| 同域难负例 ×5 | 11 | 0.960 | 1.000 | 1.000 | 0.980 |
| 同域难负例 ×全部 | 16 | 0.880 | 1.000 | 1.000 | 0.940 |
| 无关全部 + 难负例全部 | 42 | **0.840** | 1.000 | 1.000 | **0.913** |

完整明细（含逐条 gold rank）：`backend/retrieval_bm25_report.json`。

#### 4.2.4 解读

1. **无关干扰几乎不掉：检索器能区分主题。** 26 段无关 chunk 全部入索引后 MRR 仅
   1.0 → 0.98（1 条查询被顶到第 2）。词面匹配对"主题隔离"足够——查询里的
   "退货/售后/凭证"等词项在无关语料里零出现。
2. **同域难负例才是真压力：词面匹配在近义政策文本上力不从心。** 3 条查询被顶到
   第 2 名，最典型的是"7天无理由退货的起算时间是什么时候？"输给"优选商城支持
   5天无理由退货…自签收次日起算"——**只差一个数字，bigram 层面不可分**。这是
   真实的检索质量信号，不是构造出来的，也正是"为什么需要向量检索/精排"的
   教科书证据。
3. **H@3/H@5 恒为 1.0**：金标只有 6 个且查询词项具体，BM25 总能把它排进前 3。
   饱和是本实验的设计边界（见 4.3），但 H@1/MRR 的单调退化足以证明确定性指标
   能区分检索质量差异。
4. **排序与行类别正交**：金标掉到第 2 的行同时出现在 correct 与 hallucinated 两类
   中（截断类未出现），与"检索质量和生成质量解耦"的分层设计一致。
5. **规则版 recall 恒 1.0**（top-K 内容级覆盖答案的 sanity 检查），但**规则版
   precision 已被移除**——见 4.2.5。

#### 4.2.5 一次诚实的取舍：规则版 precision 被移除

原方案里"自研规则版上下文相关性（查询覆盖度阈值法）随噪声下降"是证据之二，但
实测发现该启发式对问句-段落匹配**不可校准**：按句覆盖度（阈值 0.4）在纯知识库下
仅 0.13、整 chunk 覆盖度 0.21，且随同域难负例注入**反向微升**（硬负例与金标共享
词汇，覆盖度无法区分）——短中文问句的词项太少，覆盖度对"相关/不相关"无判别力。
与其报一个不可解释的数字，不如移除并在脚本注释里记录原因。规则版对标改走
RAGAS NonLLMContextPrecision/Recall 并已完成（见 4.2.7），那套实现经过业界
校准，不重复造轮子。

#### 4.2.6 数字的诚实边界

语料极小（6 金标 + 至多 36 干扰），H@3/H@5 饱和，**绝对数值不具工业参考意义**
（业界基线 Recall@5 87% / MRR 0.79 来自 300 条标注集）。本实验的价值是形状与
机制：无关干扰几乎不掉、同域难负例单调下降——指标能区分检索质量差异，且排序
完全由 BM25 打分决定（数据依赖已由测试把守）。

#### 4.2.7 规则版同机制对标：RAGAS NonLLM（2026-08-06，已完成）

把同一批 BM25 检索输出（四场景）喂给 RAGAS v0.4.3 的规则版指标——NonLLMContextRecall /
NonLLMContextPrecisionWithReference（Levenshtein 归一化相似度，阈值 0.5，零 LLM 零
embedding，完全确定性），与平台 ID 级指标走"确定性 ↔ 确定性"对标，跳过 LLM 判定差异
干扰。实现：`backend/scripts/compare_ragas_nonllm.py`（dump 用平台环境、score 用
RAGAS 环境，两阶段隔离），原始数字见 `backend/ragas_nonllm_report.json`（provenance:
脚本 + ragas 版本 + 距离口径）。

| 场景 | 库 | 平台 H@1 | 平台 MRR | RAGAS NonLLM recall | RAGAS NonLLM precision |
|------|----|------|------|------|------|
| 纯知识库（无干扰） | 6 | 1.000 | 1.000 | 1.000 | 1.000 |
| 无关干扰 ×全部 | 32 | 0.960 | 0.980 | 1.000 | 0.980 |
| 同域难负例 ×全部 | 16 | 0.880 | 0.940 | 1.000 | 0.940 |
| 无关全部 + 难负例全部 | 42 | 0.840 | **0.913** | 1.000 | **0.913** |

**逐场景平台 MRR 与 RAGAS NonLLM precision 完全相等。** 机制上不是巧合：单金标下
RAGAS ContextPrecision 的 AP（按检索位次对"命中/未命中"累积平均）≡ 1/rank ≡ 平台
MRR，数学等价。两个**独立实现**（平台 ID 级精确命中 vs RAGAS 字符级相似度判定）在
同一批检索上产出相同聚合值，互相交叉验证——检索侧结构效度证据成立：平台确定性
指标的排序质量口径与业界规则版一致。行级 Spearman 秩相关 -1.0（rank 与 AP 完全
负秩相关）同样是该数学等价的必然，非额外信息；纯知识库场景全 tie，Spearman 无定义
（报告记为 None）。

**饱和边界同样适用 NonLLM**：recall 恒 1.0 与平台 H@5 恒 1.0 同因——金标总能被
BM25 排进 top-5，内容级覆盖必然命中。这与 4.2.3 解读第 3 点的 H@3/H@5 饱和是同一个
设计边界，不构成"两个实现都错"，而是二者共享同一检索输入。

#### 4.2.8 检索侧准则效度：人工黄金集（2026-08-06，已完成）

对最重压力场景（无关 26 + 同域难负例 10，库 42）的 25 条查询逐条标注「期望命中的
chunk」：初标（独立判定）→ 用户逐条人工严格复核 → **25/25 判定一致**，人工审核
确认为最终真值（`backend/scripts/retrieval_goldset_annotations.json`，
provenance 含人工复核记录）。判定标准：金标是否包含查询答案的唯一合理来源；
同主题但商城/数值不同的难负例（优选商城）不视为答案来源——会误导回答。

结果（`backend/scripts/compute_goldset_agreement.py`，原始输出
`backend/retrieval_goldset_agreement.json`）：

- 判定分布：**Y 23 / MULTI 2 / N 0**——人工审核未发现任何金标构造错误；
- **金标 ∈ 人工期望集 25/25**：合成数据集"每条查询唯一 source chunk"的构造
  经人工审核成立；
- 金标口径与人工黄金集口径 **H@1 / MRR 完全一致（0.840 / 0.9133）**：检索器排序
  质量在人工真值下同样成立，检索侧准则效度证据落地；
- **2 条多来源（行 6/19）**：验收后退款时限同时见于第 2 节退货流程与第 8 节
  售后时效——同一答案信息跨 chunk 重复，是合成数据集按节切分的固有局限，
  但两处金标均排在 top-1，不影响评分；
- 有意义的是**形状而非数值**：难负例在人工判定下同样不构成答案来源
  （hardneg-0/4/6/7 同主题反义或异数值，人工全部排除），印证同域难负例的
  "看似相关实则错误"构造有效。

## 五、前沿方法调研与本项目成熟度评估

调研时间：2026-08。三路并行调研：① RAG 评测前沿（RAGAS 演进/黄金集/检索评测/归因评测）；

### 5.1 对本项目直接相关的前沿事实

**（1）RAG 评测**
- RAGAS 最新 v0.4.3（"V2 指标架构"= collections API 重构）；answer_relevancy 机制未变；
  FactualCorrectness 升级为 **claim-level + NLI 双向验证**（Precision/Recall/F1 模式）；
  新增 **CitationAccuracy**（引用准确率，judge 只依据被引段落判定）；
- 检索指标分 LLM 版与**规则版**（NonLLM 字符串相似度，阈值 0.5）；
- 检索评测黄金集自动化：RAG-GS 六阶段流水线；无黄金集替代：LLM judge QA 模式
  （与人工标签 Pearson 0.91）、Search Self-Play（零标注反推证据）、RAG-Zeval（RL 训练评测器）；
- 归因评测主流：claim 分解 + 被引段落约束判定（RAGChecker/MIRAGE 证实 subclaim 分解
  与人类判断一致性最高）。

**（2）LLM-as-a-Judge**
- 偏置是**结构性**的：12 类偏置（CALM）、self-bias 线性回归量化（同族模型加 10-25% 分）、
  **style bias 0.76-0.92 远超 position bias**；缓解组合拳：换序互评 + rubric + 强制 CoT +
  跨家族多裁判 + 人工校准（kappa ≥ 0.7）+ 校准集每周复评；
- 小模型 judge 是成本方向：JudgeLM（7B 与 teacher 一致率 >90%）、PoLL 陪审团
  （1/7 成本超单 GPT-4 judge）、TIR-Judge（8B 代码执行式 judge 达 ~96% listwise）；
- 理论极限（ICLR 2025）：judge 不比被测模型强时，去偏方法最多把人工标注需求减半。

**（3）Agent 评测**
- Agent-as-a-Judge（与人类一致率 ~90% vs 单 LLM judge ~70%，成本降 97%）；
- 执行式/状态式评测是黄金标准：BFCL 执行评测、tau-bench 目标状态比对 + **pass^k**、
  SWE-bench 测试套件（且已因污染被弃用 → 动态防污染基准成为趋势）；
- 轨迹评测成为方法论重心：step efficiency、反模式检测（循环/thrashing/错误级联）、
  轨迹 vs 结果双层评测（SABER：单个 mutating 偏差使成功率降 55-92%）；
- 基准自身需要被攻击测试：BenchJack 不解决任务拿到满分（100% hack Terminal-Bench）。

**（4）评测集构建与工业闭环**
- 合成数据生成 + 三重校验（嵌入 judge 过滤 + 可回答性 + 人工抽检）是主流；
- 防污染从"检测清洗"转向"动态生成 + 时间隔离 + 层级检测"组合拳；
- 人工黄金集规模阶梯：50-100 条起步（"50 条精心挑选 > 500 条随机"），
  发布前 200-500 条；**黄金集保持约 20% 失败率**（全过说明集子太简单）；
- 工业闭环已标准化：离线 golden set + 线上 A/B + judge 工程化
  （rubric/CoT/人工校准 kappa/成本采样 3-5%）+ badcase 回流 + CI 门禁；
  代表体系：阿里 EvalScope、字节扣子罗盘（国内首家轨迹评测）、蚂蚁 EBDD 范式、
  Braintrust/Langfuse/Weave（指标 → 数据集 → 实验 → 报告四件套结构）。

### 5.2 本项目成熟度评估

**与 2026 前沿对照，本项目的强项（符合共识的设计）**：

| 维度 | 现状 | 前沿共识对照 |
|------|------|-------------|
| 评测闭环结构 | 数据集 → 场景 → 任务 → 报告 → 人工复核 → 盲测 → 对比，全 Web UI | 与 Braintrust/Langfuse/Weave/扣子罗盘的四件套结构一致 |
| 人工复核内建 | 报告页逐条复核 + 自动/人工一致性统计 | 符合"judge 是测量系统而非真值，须人工校准"共识 |
| 确定性指标优先 | HitRate@K/MRR/工具调用匹配全部确定性零成本 | 符合"执行式/确定性评测优先"趋势 |
| 可复现性 | 场景快照冻结 + 历史回填 | 符合腾讯"四可"承诺中的可复现要求 |
| 盲测去偏 | md5 随机化左右展示 | 符合位置偏置缓解共识（基础版） |
| 信度量化 | 多采样标准差 + 低置信度标记 | 符合重测信度要求 |

**差距清单（对照前沿）**：

| # | 差距 | 前沿做法 | 影响 | 优先级 |
|---|------|----------|------|--------|
| 1 | Judge 工程化不完整 | 换序互评、强制 CoT、跨家族多裁判、kappa≥0.7 人工校准闭环、校准集周复评防漂移 | "LLM-as-judge 可信吗"追问的最深处 | P1 |
| 2 | 无归因/引用评测 | CitationAccuracy（judge 只看被引段落） | 幻觉治理的后半段（misattribution 是主要失败模式） | P1 |
| 3 | Agent 评测缺轨迹层 | 轨迹记录 + 反模式检测 + 轨迹级 judge（Agent-as-a-Judge） | Agent 场景定位问题只能靠结果反推 | P2 |
| 4 | 评测集无版本化/防污染 | 数据集版本化（git 式）、n-gram+嵌入相似度污染检测 | "高命中率是否可信"追问 | P1 |
| 5 | 无 CI 门禁集成 | promptfoo/DeepEval 式 eval-as-code + PR 门禁 | 工程闭环的最后一块 | P2 |
| 6 | 无在线评测 | 线上 trace 采样打分 + 失败回流 | 数据飞轮的上游 | P3 |
| 7 | 检索侧结构效度缺失 | 规则版对标 + 噪声注入（见第四章方案） | 实验边界（已知） | P0 |
| 8 | 小模型 judge/成本采样 | JudgeLM/PoLL 陪审团、成本感知采样 3-5% | 规模化成本 | P3 |

**成熟度结论**：本项目在"评测闭环结构、人工复核内建、确定性指标、可复现性"上已达到
2026 工业标准；主要差距集中在 **judge 工程化深度（偏置缓解/校准闭环）、归因评测、
轨迹评测、评测集治理**——这些都是面试中"你了解评测前沿吗"的深水区，也是优化后
可以讲出"评测体系迭代"故事的方向。

## 七、结论

1. 本项目评测系统的**区分度**已被真实实验证明（错误注入敏感、检索/生成解耦）；
2. **结构效度**部分成立：断言级 faithfulness 与 RAGAS 排序高度一致
   （Spearman 0.8173，整体版 0.7567，n=25 混合集，均为缺陷 A/B 双修复后口径）；
   answer_relevancy 修复后仅弱相关（Pearson 0.3728 / Spearman 0.2391），原因是
   真实机制差异而非缺陷——RAGAS 的"反向提问 + 嵌入相似度"在结构上无法惩罚截断，
   平台裁判会；修复前那点较高的相关是泄露掩盖出来的"对的分数、错的理由"；
3. **准则效度**已有首轮实测（2026-08-06）：25 条人工标注 vs 自动判定，一致率
   0.72、kappa 0.4582（中等一致）——方向共识成立；分歧 6/7 为"自动过松"且集中在
   截断/幻觉类，与信度方差分层同构，是**可操作的校准信号**而非测量失效；
4. 检索侧指标非能力缺失，而是实验设计边界——**已用 BM25 端到端检索实验补齐**：
   无关干扰几乎不掉（MRR 1.0→0.98，主题可分）、同域难负例单调下降（MRR 1.0→0.94、
   H@1 0.88→0.84，词面匹配在近义政策文本上的真实局限），确定性指标具备区分度；
   待做：黄金集人工标注 + RAGAS NonLLM 规则版对标（第四章 4.2-4.3）；
5. **前沿调研确认**：项目在评测闭环结构、人工复核内建、确定性指标、可复现性上已达到
   2026 工业标准；主要差距集中在 judge 工程化深度（偏置缓解/校准闭环）、归因评测、
   轨迹评测、评测集治理——已全部落入第六章路线图；
6. 全部实验数据、脚本、方法论文档均已沉淀在仓库，可复现、可扩展。
