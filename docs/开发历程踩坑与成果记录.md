## 二、分阶段详细记录

### 阶段 0：MVP 搭建（04-21 ~ 05-12）

**做了什么**：前后端初始化 → 评测引擎（LLM-as-a-Judge，双层 prompt：系统层管输出协议、
业务层判分标准存 DB 可覆盖）→ 数据集管理 → RAG 数据集生成器（结构化文档切分 +
LLM 问题生成）→ 接口实时评测与自定义指标链路 → 多轮/Agent 场景支持。

**踩的坑**：
- **加密密文问题**（`52d84ed`）：LLM 配置的密钥在存储/回显链路有加解密不一致，
  导致配置无法正确回读。解决：统一加密/解密路径，补测试。
- 早期同主题提交多次出现（`73c1008`/`86f00ad`、`942f3ea`/`58bc4a2` 等成对出现），
  是历史整理时的重提交，与功能无关。

**成果**：平台全链路可用（前端评测页 + 报告详情页 + 数据集管理 + 后端引擎），
`5042e3e` 合并进 main。

### 阶段 0.5：开源准备（06-17 ~ 07-20）

README 中英文拆分、发布前清理、roadmap + v0.1.0 changelog。无实质踩坑。

### 阶段 1：评测可靠性 + 元评价体系（08-06，`b90c2ba`）

**做了什么**：加权总分（场景快照权重聚合）、Judge 可靠性量化（`EVAL_JUDGE_SAMPLES`
多采样 + 采样标准差 + 低置信度标记）、成本统计、人工一致性（kappa）、WebSocket
实时进度、任务陈旧回收、RAGAS 对照脚本 + 元评价方法论文档。

**踩的坑**（每个都是"问题表现 → 根因 → 最小修复"）：
1. **WebSocket 跨事件循环线程安全**：后台任务线程推送进度到主事件循环，直接推会
   竞态。解决：线程安全推送封装 + 断线自动回退轮询。
2. **任务陈旧回收误杀**：长任务被误判为陈旧而回收。解决：心跳机制防误杀。
3. **RAGAS 0.4.3 导入即崩**：langchain-community 0.3+ 移除了 `vertexai` 模块，
   RAGAS 仍硬编码导入。解决：项目内最小 shim（`backend/scripts/_shims/`），
   仅对照实验运行时生效，不污染平台代码。
4. **Qwen3 thinking 模式把调用拒了**：RAGAS 的 answer_relevancy 一次请求 n=3，
   默认开启 thinking 的模型拒绝。解决：ChatOpenAI 注入 `extra_body={"enable_thinking": false}`。
5. **embedding 长度安全路径损坏输入**：langchain 默认走 tiktoken 白名单路径，
   模型名不在白名单导致 input 损坏。解决：`check_embedding_ctx_length=False` 走直传路径。

**成果**：评测结果从"一个数"变成"可信可复现的数字"；元评价四层体系（区分度/
结构效度/信度/实用性）落地为文档 + 实验脚本。

### 阶段 2：双通道指标 + Judge 工程化 + 评测集治理（08-06，`9eee48d`）

**做了什么**：
- **双通道指标**（全部原生实现，不依赖第三方评测框架）：
  - 生成式相关性：反推问题 + OpenAI 兼容 embedding 语义相似度；
  - 断言级忠实度：原子断言拆解逐条核验；
  - 与整体判定指标并存交叉验证。
- **Judge 工程化**：强制 CoT（`JUDGE_COT_MODE`）、换序互评防位置偏置
  （`EVAL_SWAP_CHECK`：反转列表字段复评 + 一致性聚合）、多裁判面板
  （`judge_llm_config_ids`：均值/多数票聚合 + 裁判间 MAD）。
- **人工校准闭环**：报告自动算人工 vs 自动 Cohen's kappa，<0.7 提示修订判分标准。
- **数据集版本化**：行级变更自增版本，任务创建时冻结 dataset_version。
- **评测集治理工具**：零依赖中文 BM25 mock 检索引擎、检索噪声实验、n-gram +
  embedding 双信号污染检测。

**成果**：76 测试通过；生成侧从单一判定升级为"整体 + 断言级/生成式"双通道。

**⚠ 事后发现的坑（重要）**：本阶段提交信息宣称噪声实验"验证通过：MRR 1.0→0.09
随噪声单调下降"——**该实验后来（阶段 6）被证明是闭式循环**：检索结果是
`noise_ids + reference_ids` 拼出来的，MRR 恒等于 1/(n+1)，与数据无关。教训：
"数字单调下降"本身不能证明测量有效，必须先证明测量结果依赖真实数据。

### 阶段 3：前端多裁判面板 + 审查修复（08-06，`d88da01`）

**做了什么**：前端评测执行页新增附加裁判 LLM 多选（排除主裁判，克隆任务继承面板）。

**踩的坑（审查阶段修出 5 类 bug）**：
1. **seed.py 新指标注册语法破坏 + 重复插入**：main/upgrade 两路径各注册一次。
2. **`_aggregate_judge_results` 误入离散多数票分支**：部分裁判缺分时聚合逻辑出错。
3. **换序互评 token 用量漏记成本**。
4. **`_normalize_metric_summary` 摘要键未先取出就归一化**：内部键暴露。
5. **噪声实验脚本死代码**（后来阶段 6 的伏笔）。

**验证**：76 测试通过 + 前端构建通过 + 全模块导入 OK。

### 阶段 4：claim 分解质量（08-06，`d60c15c`）

**踩的坑（验收发现的真实质量问题）**：分解 prompt 把评价性句子当"无信息量"
过滤 → **答非所问的行分解为空断言 → 触发 1.0 宽松兜底 → 忠实性虚高**。
空断言兜底改 0（未基于上下文作答 = 未扎根，与 RAGAS 行为一致），同时保留
意见性断言（可被上下文支持或反驳）。

**验证**：错误注入集复验——无关回答行 claim 0.0（"今天天气不错 ✗ / 适合散步 ✗"
逐条可读），四指标全部归零，双通道口径一致。新增空断言兜底=0 测试，79 通过。

### 阶段 5：RAGAS 对照实测 + 缺陷 A/B（工作区，本次提交）

对照实验最大产出不是"自研指标和 RAGAS 有多像"，而是照出**平台自己的两个测量污染缺陷**。

**缺陷 A：样本真值标签泄露给裁判**。评测集每行带 `generation_meta =
{"kind": "correct|hallucinated|truncated"}`，下发 payload 的兜底循环把样本内
所有字段无差别交给裁判 → **100 个 judge prompt 里 64 个带标签** → 区分度和
一致性同时虚高（裁判锚定标签后换序互评自然更"稳定"）。
**解决**：`_JUDGE_HIDDEN_FIELDS` 黑名单 + 单元 + 端到端两层回归测试；关闭修复后
泄露立即重现，证明测试不是空转。

**缺陷 B：`required_fields` 不约束实际下发字段（口径越界）**。`required_fields`
只校验"字段是否存在"，不裁剪 payload，于是检索侧指标看得见 `response`、只判
"是否回应问题"的 answer_relevancy 看得见 `reference`。
**证明因果**（A/B 实验 `ab_response_leak.py`，同批 8 条幻觉样本唯一变量是
`response` 有无）：context_recall 0.7875→1.0000、context_precision 0.8125→1.0000，
与 RAGAS 逐行一致。
**修复过程的第二个发现：原定方案本身是错的**。"按 `required_fields` 严格裁剪"
会打断 17 个内置指标里的 **9 个**：8 个 Agent/多轮指标判的就是 AI 回复却没把
`response` 列为必需（运行时才注入，列为必需会让 dataset 模式整批判缺失）；
`context_precision` 的判定文字要看 `reference` 而它不声明必需。
**根因**：一个字段被当成两件事用——校验门槛 vs 裁判可见范围，两个集合本就不相等。
**实际修复**：拆出独立 `judge_fields` 口径，17 个指标逐个显式声明；`_sample_payload`
新增白名单模式并整段跳过兜底循环（缺陷 A 与 B 的共同载体）。5 个回归测试 +
结构不变量测试（每个 spec 的 judge_fields 覆盖 required_fields）。

**过程中的技术坑**：A/B 脚本 `sys.path` 指向 `/tmp` 导致 0 字节输出（路径 bug）；
报告 JSON 的 `rows` 是计数不是列表（TypeError）。均为定位修复。

**修复后 n=25 实测**（RAGAS 逐行分复用、逐行核对未变）：
- 检索侧：context_recall / context_precision **逐行等于 RAGAS**，分层总偏离
  0.275→0.000、0.213→0.000——平台检索侧那点方差 100% 是缺陷 B 的产物，无一是检索信号；
- 生成侧如实说明：answer_relevancy 幻觉样本偏离 0.284→0.028，但与 RAGAS 相关性
  略降（0.439→0.373）——**泄露此前掩盖了一个真实机制差异**：拿掉 `reference` 后
  裁判对截断样本两极判断，而 RAGAS 的反推问题 + embedding 相似度结构上惩罚不了截断。
  决策：选择声明口径的正确性，而不是相关性数字；
- 双通道优势在修复后扩大：Pearson +0.047→+0.071、Spearman +0.007→+0.061，
  截断样本上断言级偏离是整体版的 1/3.6。

**测试非空性验证**：用 pytest 插件 monkeypatch 模拟修复前行为（不改源码），
3 个 bug-guard 测试如预期失败、过修正守卫测试仍通过——证明测试真实抓 bug。

### 阶段 6：检索侧补齐（工作区，本次提交）

**坑（最值钱的一个）**：阶段 2 提交的"已验证"噪声实验是**闭式循环**。动手前先做
数值验证：`noise_ids + reference_ids` 的构造下金标恒定排第 n+1 位，MRR ≡ 1/(n+1)、
HitRate@5 ≡ (n<5)——与数据集内容、检索器质量、chunk 文本全部无关，换一份完全
不相干的数据也是同一串数字。**把它当区分度证据是循环论证**，原脚本废弃。

**解决**：重写为真实 BM25 检索——
- 检索结果唯一来源是 BM25 排序，任何位置不拼 `reference_context_ids`；
- 双干扰语料：无关 26 段（`_fixtures/distractor_corpus.md`，手机/咖啡/编程/旅行，
  零词汇重叠）+ 同域难负例 10 段（`_fixtures/hard_negatives.md`，虚构"优选商城"
  售后政策，同主题同术语不同数字）；
- **守门测试 `test_ranking_is_data_dependent`**：把金标正文换成无关文本后 H@1 必须
  归零——同义反复的实现过不了这条，防回归。

**实测**（25 条互异查询，每条 1 个金标 ID）：

| 场景 | 库 | H@1 | H@3 | H@5 | MRR |
|------|----|-----|-----|-----|-----|
| 纯知识库（无干扰） | 6 | 1.000 | 1.000 | 1.000 | 1.000 |
| 无关干扰 ×全部(26) | 32 | 0.960 | 1.000 | 1.000 | 0.980 |
| 同域难负例 ×全部(10) | 16 | 0.880 | 1.000 | 1.000 | 0.940 |
| 无关全部 + 难负例全部 | 42 | **0.840** | 1.000 | 1.000 | **0.913** |

**解读**：无关干扰几乎不掉（主题可分，词面匹配足够）；**同域难负例才是真压力**——
"7天无理由退货的起算时间"输给"优选商城支持5天无理由退货…自签收次日起算"，只差
一个数字，bigram 层面不可分。这是真实检索质量信号，也是"为什么需要向量检索/精排"
的教科书证据。金标掉排名的行同时出现在 correct 与 hallucinated 两类中（与
"检索质量和生成质量解耦"的分层设计一致）。

**坑：规则版 precision 不可校准**。原方案把"查询覆盖度阈值法"当证据之二，实测
按句覆盖度（阈值 0.4）纯知识库下仅 0.13、整 chunk 覆盖度 0.21，且随难负例注入
**反向微升**（硬负例与金标共享词汇，覆盖度无法区分）——短中文问句词项太少，
该启发式无判别力。与其报一个不可解释的数字，**移除并在脚本注释里记录原因**；
规则版对标路径留给 RAGAS NonLLM（业界校准过，不重复造轮子）。

**验证**：23 个新测试（BM25 单元 + 实验守门/完整性/语义），全量 **109 通过**。

## 三、贯穿性方法论（可迁移，面试可讲）

1. **先质疑测量本身**。本项目的三次大坑（闭式循环、标签泄露、口径越界）本质是
   同一个问题：数字好看，但测量对象与声称的对象不一致。每次都是"先证明测量有效，
   再读数字"。
2. **修复前先枚举全部调用点**。judge_fields 方案若直接按原定方案做会打断 9/17
   指标；动手前枚举 17 个内置指标避免了这次破坏。"一个字段两个职责"是根因，
   拆分职责而非加特例。
3. **测试必须证明非空转**。关闭修复 → 测试失败（缺陷 A/B 都验证过）；守门测试
   用"数据变了结果必须变"来防同义反复。
4. **报告数字必须带来源**。合并报告每个指标带 `_provenance`（数据来源文件、
   运行时间、缺陷修复状态），任何数值不靠人工转抄。
5. **诚实的取舍**。规则版 precision 移除、answer_relevancy 相关性下降的机制解释、
   检索侧绝对数值不具工业意义的边界声明——报可解释的数字，不报好看的数字。
6. **最小 shim 原则**：第三方库兼容问题用项目内 shim 解决（`_shims/`），
   平台代码零依赖第三方评测框架（避免被误认为 fork RAGAS/DeepEval）。
