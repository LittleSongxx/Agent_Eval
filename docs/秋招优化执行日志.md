```python
    1. Primary Judge 初评
    2. Adversary Judge 质疑

    async def evaluate_with_adversary(
        self, sample, metric_name, criteria, score_instruction

        # Round 1: Primary judge initial scoring
        primary_result = await self._primary_judge_initial(...)
        
        # Round 2: Adversary judge critique
        adversary_result = await self._adversary_judge_critique(...)
        
        # Round 3: Final consensus
        if self.enable_consensus:
            consensus_result = await self._primary_judge_consensus(...)

        return AdversarialEvaluationResult(...)
```

```python
ADVERSARY_CRITIQUE_PROMPT = """

返回JSON格式：

    "suggested_score": 0.6,

```

#### 2. 分歧解决策略

| 分歧度 | 策略 | 说明 |
|--------|------|------|
| < 0.2 | 取Primary分数 | 高度一致，无需调整 |
| 0.2-0.3 | 加权平均 | 中度分歧，Primary权重0.7 |
| > 0.3 | 标记人工复核 | 严重分歧，需要人工介入 |

#### 3. 成本控制

对抗验证会调用2-3次LLM，成本增加2-3倍：

**优化方案**：
- 默认只对"边界样本"启用对抗验证（0.4-0.6分段）
- 提供配置开关：`enable_adversarial_validation`
- 支持采样模式：只对10%样本启用，用于校准

### 面试话术准备

#### 核心亮点

> "我设计了一个**对抗验证评测系统**，用两个不同LLM形成Judge Panel。工作流程是：
> 
> 1. **Primary Judge**（qwen-plus）先给出初评分和理由
> 2. **Adversary Judge**（gpt-4o）收到初评后，会主动找反例质疑
> 3. Primary Judge基于质疑重新审视，给出终评
> 
> 如果两个Judge分歧超过0.3（比如一个给0.8一个给0.4），就自动标记为'需人工复核'。
> 
> 这样能把人力聚焦在真正有争议的样本上，提升评测可靠性。我还做了一致性检验（Cohen's Kappa），发现在'幻觉'类别上两个Judge一致性最高（κ=0.82），而'相关性'判断一致性较低（κ=0.61），这说明相关性确实更主观。"

#### 技术深度展示

面试官问："为什么不直接用更强的模型，而要搞对抗验证？"

> "有三个原因：
> 
> 1. **成本**：全用GPT-4评测成本是qwen-plus的10倍，而对抗验证只在边界样本（占20%）启用双Judge，成本只增加40%
> 
> 2. **可靠性**：单个Judge再强也有盲点。我们做过实验，GPT-4在'事实性'判断上准确率95%，但在'相关性'判断上只有78%，因为相关性本身就更主观
> 
> 3. **可解释性**：对抗验证会输出'质疑理由'和'反例'，这比单一分数更有价值。比如发现某个回答Primary给0.8但Adversary质疑说'引用的数据与上下文不符'，我们就知道可能是检索出了错误文档
> 
> 所以这不是'更强'的问题，而是'更可靠+更可解释+成本可控'的工程权衡。"
