# 项目一页纸：AI 评测平台——"测量可信"的技术验证

## 一句话

面向 RAG / AI Agent / 多轮对话场景的 AI 评测平台：FastAPI + React + SQLite，
LLM-as-a-Judge 评测内核，17 个内置指标；**核心差异化不是功能数量，而是用
"元评价"（对评测本身的评测）把"平台给的分数可信"这件事做到有实测证据。**

## 技术栈与架构

- 后端 FastAPI + SQLAlchemy + SQLite，异步评测任务 + WebSocket 实时进度；前端
  React 18 + TypeScript + Ant Design 5
- 评测内核：双层 prompt（系统约束 + 指标判分标准），强制 CoT，严格 JSON 输出
- 平台零依赖第三方评测框架（RAGAS/DeepEval 只用于对照实验），无 fork 争议

## 关键数字（全部来自脚本输出，带 provenance）

**元评价四维体系——全部有实测数据（2026-08）**

## 亮点故事（面试可讲 3 分钟）

1. **识别并废弃了"已验证"的假实验**：团队提交说噪声实验通过（MRR 单调下降），
   我用数值验证发现它是闭式构造——检索结果直接拼了金标，MRR ≡ 1/(n+1) 与数据
   无关。换数据重写为真实 BM25 检索 + 守门测试防回归。
2. **定位两个测量污染缺陷**（裁判可见真值标签 / 检索指标口径越界看到回答）：
   通过"平台分与 RAGAS 在分层数据上系统性背离"这一信号定位，修复后检索侧
   逐行等于 RAGAS——证明原来的方差 100% 是缺陷伪影。
3. **人工校准闭环**：kappa 0.4582 → 逐行证据 + 业界基准调研（不盲目调参）→
   只改该改的（判分标准执行漏判 + 阈值政策），保留定义边界（faithfulness
   不惩罚截断 = RAGAS 业界共识）→ 重跑验证。
