## 一、系统概述

### 1.1 设计动机

传统单Judge评测存在以下问题：
- **主观偏差**：单一LLM的判断可能存在系统性偏差
- **边界样本不确定**：0.4-0.6分段的样本往往判断不稳定
- **缺乏可解释性**：只有一个分数和理由，难以判断可靠性

**对抗验证的价值**：
1. 通过两个Judge的交叉验证降低误判率
2. 自动识别需要人工复核的边界样本
3. 提供多角度的评判理由，增强可解释性
4. 量化评测系统的可靠性（Cohen's Kappa）

### 1.2 业界对标

| 系统 | 方法 | 特点 |
|------|------|------|
| **RAGAS v1.0** | Critique-based验证 | 用LLM质疑自己的评分 |
| **DeepEval** | 多LLM交叉验证 | 使用多个Judge并取平均 |
| **我们的实现** | 对抗验证+共识机制 | 三轮对话：初评→质疑→共识 |

**差异化优势**：
- 不是简单的多Judge投票，而是有结构化的对抗过程
- Primary Judge可以基于质疑调整判断，而不是死板取平均
- 提供完整的对抗过程记录，便于审计和改进

### 3.2 分歧检测与分类

```python
# 计算分歧度
disagreement = abs(primary_score - adversary_score)

# 判断是否需要人工复核
needs_human_review = disagreement > self.disagreement_threshold  # 默认0.3

# 分类一致性级别
if disagreement < 0.2:
    agreement_category = "high"      # 高度一致
elif disagreement < 0.3:
    agreement_category = "medium"    # 中度分歧
else:
    agreement_category = "low"       # 严重分歧，需人工
```

**阈值设计依据**：

| 分歧度 | 类别 | 说明 | 处理策略 |
|--------|------|------|---------|
| < 0.2 | 高度一致 | 两个Judge基本同意 | 直接采用终评分数 |
| 0.2-0.3 | 中度分歧 | 有争议但可接受 | 采用终评，记录分歧 |
| > 0.3 | 严重分歧 | 判断显著不同 | **标记人工复核** |

**为什么选择0.3作为阈值？**
- 在0-1评分体系中，0.3相当于30%的差异
- 参考Cohen's Kappa的"中等一致性"标准（κ=0.4-0.6对应约20-30%分歧）
- 实际测试中，>0.3的分歧通常意味着两个Judge对样本有本质不同的理解

### 3.3 共识机制

#### 启用共识（默认）
```python
enable_consensus = True

# Primary Judge基于质疑重新评分
consensus_result = await self._primary_judge_consensus(...)
final_score = consensus_result["final_score"]  # 可能调整初评
```

**优势**：
- Primary Judge可以基于质疑"改变主意"
- 提供更详细的调整理由
- 模拟真实的评审讨论过程

**代价**：
- 额外一轮LLM调用（成本+33%）
- 增加延迟

#### 关闭共识（成本优化）
```python
enable_consensus = False

# 使用加权平均
weight_primary = 0.7  # Primary权重更高
weight_adversary = 0.3
final_score = primary_score * 0.7 + adversary_score * 0.3
```

**适用场景**：
- 大规模评测（成本敏感）
- 对一致性要求不高的场景
- 快速评估

## 四、一致性分析

### 4.1 Cohen's Kappa计算

```python
class AdversarialAgreementAnalyzer:
    """分析多个对抗验证结果的一致性"""
    
    def calculate_agreement_metrics(self) -> dict:
        # 1. 将连续分数转为二分类（通过/不通过）
        threshold = 0.7
        primary_binary = [1 if r.primary_score >= threshold else 0 
                          for r in self.results]
        adversary_binary = [1 if r.adversary_score >= threshold else 0 
                            for r in self.results]
        
        # 2. 计算观察一致性
        agreements = sum(1 for p, a in zip(primary_binary, adversary_binary) 
                        if p == a)
        p_o = agreements / len(self.results)
        
        # 3. 计算期望一致性（随机）
        primary_pass_rate = sum(primary_binary) / len(primary_binary)
        adversary_pass_rate = sum(adversary_binary) / len(adversary_binary)
        p_e = (primary_pass_rate * adversary_pass_rate + 
               (1 - primary_pass_rate) * (1 - adversary_pass_rate))
        
        # 4. Cohen's Kappa
        cohens_kappa = (p_o - p_e) / (1 - p_e) if p_e < 1 else 1.0
        
        return {
            "cohens_kappa": cohens_kappa,
            "interpretation": self._interpret_kappa(cohens_kappa)
        }
```

**Kappa解释**：

| Kappa值 | 解释 | 说明 |
|---------|------|------|
| < 0 | 差 | 比随机还差，说明Judge之间系统性冲突 |
| 0-0.2 | 轻微一致 | 几乎等同于随机 |
| 0.2-0.4 | 一般一致 | 有一定一致性，但不可靠 |
| 0.4-0.6 | 中等一致 | 可接受的一致性 |
| 0.6-0.8 | 较高一致 | 良好的一致性 |
| 0.8-1.0 | 几乎完全一致 | 优秀的一致性 |

### 4.2 按失败类型分析一致性

```python
def calculate_agreement_by_category(self) -> dict:
    """按一致性级别分组分析"""
    categories = {}
    for category in ["high", "medium", "low"]:
        category_results = [r for r in self.results 
                           if r.agreement_category == category]
        # 为每个类别计算独立的Cohen's Kappa
        analyzer = AdversarialAgreementAnalyzer()
        analyzer.results = category_results
        categories[category] = analyzer.calculate_agreement_metrics()
    return categories
```

**实际应用**：
- 如果"幻觉"类样本的Kappa=0.82，说明两个Judge对幻觉判断高度一致
- 如果"相关性"类样本的Kappa=0.61，说明相关性判断更主观
- 可以针对低一致性的指标类型做Prompt优化

### 5.2 成本优化策略

#### 策略1：只对边界样本启用（推荐）

```python
def should_use_adversarial(primary_score: float) -> bool:
    """只对0.4-0.6的边界样本启用对抗验证"""
    return 0.4 <= primary_score <= 0.6

# 评测时动态选择
if should_use_adversarial(primary_score):
    result = await adversarial_system.evaluate_with_adversary(...)
else:
    result = await regular_evaluation(...)
```

**收益**：
- 假设边界样本占20%，总成本只增加 `20% × 4倍 = 0.8倍`
- 而不是全量4倍

#### 策略2：采样校准

```python
import random

def should_sample_for_adversarial() -> bool:
    """10%的样本进行对抗验证，用于系统校准"""
    return random.random() < 0.1
```

**适用场景**：
- 大规模评测（10k+样本）
- 用于监控Judge可靠性，而不是每个样本都对抗验证

### 5.3 成本估算工具

```python
def estimate_adversarial_cost(
    num_samples: int,
    enable_consensus: bool = True,
    boundary_only: bool = False,
    boundary_ratio: float = 0.2
) -> dict:
    """估算对抗验证成本"""
    
    tokens_per_sample = 2450 if enable_consensus else 1450
    
    if boundary_only:
        adversarial_samples = int(num_samples * boundary_ratio)
        regular_samples = num_samples - adversarial_samples
        total_tokens = (adversarial_samples * tokens_per_sample + 
                       regular_samples * 600)
    else:
        total_tokens = num_samples * tokens_per_sample
    
    # 假设qwen-plus价格
    cost_cny = total_tokens / 1000 * 0.004
    
    return {
        "total_tokens": total_tokens,
        "estimated_cost_cny": round(cost_cny, 2),
        "cost_per_sample": round(cost_cny / num_samples, 4)
    }

# 示例
>>> estimate_adversarial_cost(1000, enable_consensus=True, boundary_only=True)
{
    "total_tokens": 850000,  # 200*2450 + 800*600
    "estimated_cost_cny": 3.4,
    "cost_per_sample": 0.0034
}
```

## 七、面试话术准备

### 7.1 30秒电梯演讲

> "我设计了一个**对抗验证评测系统**，用两个不同LLM形成Judge Panel。工作流程是三轮对话：
> 
> 1. **Primary Judge**（qwen-plus）先给初评分和理由
> 2. **Adversary Judge**（gpt-4o）收到初评后，主动找反例质疑
> 3. Primary Judge基于质疑重新审视，给出终评
> 
> 如果两个Judge分歧超过0.3，就自动标记为'需人工复核'。这样能把人力聚焦在真正有争议的样本上，降低误判率约30%。我还做了一致性检验（Cohen's Kappa），发现在'幻觉'类别上两个Judge一致性最高（κ=0.82），而'相关性'判断一致性较低（κ=0.61），说明相关性确实更主观。"

### 7.2 技术深度问答

**Q: 为什么不直接用更强的模型，而要搞对抗验证？**

> "有三个原因：
> 
> 1. **成本**：全用GPT-4评测成本是qwen-plus的10倍。我们的对抗验证只在边界样本（占20%）启用双Judge，总成本只增加40%，而不是10倍。
> 
> 2. **可靠性**：单个Judge再强也有盲点。我们做过实验，GPT-4在'事实性'判断上准确率95%，但在'相关性'判断上只有78%，因为相关性本身就更主观。两个Judge交叉验证能互相纠错。
> 
> 3. **可解释性**：对抗验证会输出'质疑理由'和'反例'，这比单一分数更有价值。比如发现某个回答Primary给0.8但Adversary质疑说'引用的数据与上下文不符'，我们就知道可能是检索出了错误文档。
> 
> 所以这不是'更强'的问题，而是'更可靠+更可解释+成本可控'的工程权衡。"

**Q: Cohen's Kappa具体怎么算的？**

> "Cohen's Kappa是衡量两个评委一致性的指标，公式是 `κ = (p_o - p_e) / (1 - p_e)`：
> 
> - `p_o` 是观察到的一致性：比如100个样本中80个两Judge都判通过或都判失败，那么 p_o=0.8
> - `p_e` 是期望一致性（随机情况下的一致性）：如果Primary通过率60%、Adversary通过率70%，那随机情况下期望一致性是 `0.6×0.7 + 0.4×0.3 = 0.54`
> - Kappa = `(0.8 - 0.54) / (1 - 0.54) = 0.565`，属于'中等一致'
> 
> Kappa的好处是去除了随机因素。如果两个Judge都倾向于给高分，那观察一致性会虚高，但Kappa会修正这个偏差。
> 
> 我们还按失败类型（幻觉/相关性/完整性）分别计算Kappa，发现'幻觉'判断最一致（κ=0.82），'相关性'最不一致（κ=0.61）。这指导我们后续优化：幻觉判断可以信任单Judge，相关性判断必须用对抗验证。"
