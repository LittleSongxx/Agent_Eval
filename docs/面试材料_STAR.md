## 故事 1：识别并废弃"已验证"的假实验（工程判断力）

**S（情境）**：评测平台需要一个证据证明检索侧指标（HitRate@K / MRR）能区分
检索质量。上一手提交宣称"噪声注入实验验证通过：MRR 随噪声 1.0→0.09 单调下降"，
看起来是个漂亮的区分度证据。

**T（任务）**：接手该实验，确认它真是"指标能测出检索质量差异"，而不是数字
巧合。

**A（行动）**：动手前先做了一次数值验证——把构造过程过了一遍：检索结果 =
`噪声ID + 金标ID` 直接拼接。那么无论噪声多少、无论检索器多差、无论数据长
什么样，金标恒定位列第 n+1，MRR 恒等于 1/(n+1)。**换一份完全不相干的数据也
是同一串数字。**这不是测量，是恒等式。原脚本整体废弃，重写为真实 BM25 端到端
检索（结果唯一来源是检索器排序，代码里任何位置不拼金标），并加了守门测试：
把金标正文换成无关文本后 H@1 必须归零——**同义反复的实现过不了这条测试**。

**R（结果）**：真实检索下，无关干扰几乎不掉（主题可分）、**同域难负例才是真
压力**（"7天无理由退货起算"输给"优选商城5天…起算"，只差一个数字，bigram 层面
不可分）——MRR 1.0→0.913 单调退化。这个结论是"为什么需要向量检索/精排"的
教科书证据，且**数据依赖由测试把守**，不是一次性结论。

**可问点**：怎么判断实验是循环论证？（答：检查输出是否只依赖构造过程本身；
输出必须随数据内容变化才有意义，这成了全项目实验的通用守门标准。）

## 故事 2：测量污染缺陷的系统化定位（平台分 vs 业界分背离信号）

**S**：平台自研指标与 RAGAS 在 n=25 混合集（9 正确 / 8 幻觉 / 8 截断）上对照，
发现两处系统性背离：faithfulness 比 RAGAS 高、检索侧指标出现不该有的方差。

**T**：判定背离是"自研指标的问题"还是"平台测量的污染"，不能拍脑袋。

**A**：把背离按"分层数据"拆开看——不是看总相关系数，而是看**每一层（正确/
幻觉/截断）的偏离方向**。两个发现：(1) faithfulness 对幻觉样本几乎不降分，
但裁判 prompt 里能看到样本的"真值标签"字段——**标签泄露**：裁判直接从标签
抄答案；(2) 检索侧指标被注入 response 字段，裁判"看到回答太差"就把检索分
一起打了——**口径越界**。修复：judge_fields 白名单只传指标声明的字段 +
拆出双通道指标链路。每个修复都验证"关闭修复→测试失败"（防回归测试非空转）。

**R**：修复后检索侧**逐行等于 RAGAS**（分层偏离 0.275/0.213 → 0.000），
faithfulness Spearman 0.8173。**逆向证明了平台侧原来的方差 100% 是缺陷伪影，
没有一丝是真实检索信号**——之前怀疑"检索质量有波动"的结论被推翻。

**可问点**：为什么先怀疑污染而不是指标差异？（答：背离集中在特定分层且有
越界字段的机制解释；指标机制差异会表现为全层一致的偏差，污染表现为特定层的
异常。）

## 故事 3：人工校准闭环——不盲目调参（证据驱动决策）

**S**：平台自动触发校准建议：人工 kappa = 0.4582（< 0.7）。系统对截断/幻觉
"太宽容"，人工一律不给过。

**T**：决定怎么校准——直接调阈值？改判分标准？还是压根不该动？

**A**：三步走：
1. **逐行证据**：7 处分歧里 6 处是"自动过松"（2 幻觉 + 4 截断），把每行分数
   拆开看根因，分三层：指标定义（faithfulness 只测已说出的 claim，不惩罚截断
   ——**这是 RAGAS 的业界定义，不该"修"**）、判分执行（answer_relevancy 对
   截断给 1.0，criteria 里根本没有截断的可观察定义——**执行漏判，该修**）、
   阈值政策（0.5 vs 业界 0.7/0.8 默认——该调）；
2. **业界调研后再动**：RAGAS/DeepEval 默认阈值、首轮 judge-human kappa 0.4-0.5
   是正常水平、25 样本的 kappa CI ±0.20 只能当方向信号——**防止把正常波动
   当成失败去过度调参**；
3. **零成本模拟先验证**：用现有 25 行数据做阈值扫描（不动 LLM），统一 0.7 →
   kappa 0.4582 → 0.7458（模拟），确认方向对再动真实配置。修订 criteria 时补
   了三条操作性规则（截断可观察定义 / 防格式误杀 / 禁止裁判用常识外推扣分）。

**R**：校准落地（阈值 0.5→0.7 + criteria 修订），重跑 25 行验证（校准后 kappa
**0.8175**、一致率 0.92、自动过松清零；kappa 0.4582→0.8175 超过零成本模拟预测
的 0.7458）。**过程本身证明了平台的校准闭环机制真实跑通**：检测 → 定位 → 修复 →
复评，全部有脚本和 provenance。

**可问点**：为什么不直接统一调 0.9？（答：模拟显示 0.9 会把人工判 pass 的
"correct 类"行误杀——过拟合模拟数据，阈值政策只修到能拦住真实分歧的水平。）

## 故事 4：两个独立实现交叉验证检索侧结构效度（数学等价发现）

**S**：检索侧指标（平台 ID 级确定性指标）要证明"和业界规则版指标说的是
同一件事"，但不引入 LLM 判定差异干扰。

**T**：设计一个"确定性 ↔ 确定性"的对标实验。

**A**：把同一批 BM25 检索输出喂给 RAGAS v0.4.3 的 NonLLM 规则版指标
（Levenshtein 字符级相似度 + 阈值 0.5，零 LLM 零 embedding），与平台 ID 级
精确命中对比。跑完发现四场景**逐场景完全相等**（1.0 / 0.98 / 0.94 / 0.9133）。

**R**：为什么相等？推了下公式：单金标下 RAGAS ContextPrecision 的 AP ≡ 1/rank
≡ 平台 MRR——**数学等价**。但正因为两个实现机制完全不同（字符级相似度 vs
ID 精确命中），它们在相同输入上产出相同聚合值，才构成真正的交叉验证，而不是
同一个 bug 的两次复现。顺带标注了饱和边界（H@3/H@5 恒 1.0 是因为金标总在
top-5 内，recall 恒 1.0 同理——**两个实现共享同一检索输入的必然**，不是
"两个实现都错"）。

**可问点**：MRR 和 precision 相等会不会只是巧合？（答：数学等价是推出来的
必然，但实验的价值在于两个独立实现的一致性是"验证"而非"假设"；如果实现
有 bug，数字不会每场景都精确相等。）
