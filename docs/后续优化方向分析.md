#### 1.1 多模态评测支持（P0-5，5-7 天）

**现状**: 仅支持文本评测，无法评测图文混合、语音、视频输出

- Gemini 1.5 Pro 支持视频理解

**优化方案**:

   - 新增 `image_url` 字段到数据集
   - 支持 LLM Judge 接收图像输入（OpenAI Vision API 兼容）
   - 新增图像相关性指标（图文一致性、图像质量）
   - 示例场景：医疗报告图文匹配度、电商商品图文一致性

2. **结构化输出评测**:
   - 新增 JSON Schema 验证指标
   - 新增字段完整性检查
   - 示例场景：API 返回格式验证、表单填充准确性

3. **PDF/表格理解评测**:
   - 新增表格提取准确性指标
   - 新增公式识别准确性指标
   - 示例场景：财报分析、学术论文理解

**预期价值**:
- 拓展应用场景（覆盖多模态 RAG、视觉问答）

- 提升项目竞争力（差异化能力）

**推荐实现路径**:

#### 1.2 成本优化实验落地（2 天）

**现状**: 已有并发优化（时间优化），但缺少真正的成本优化

**问题**: token 消耗与串行相同，LLM API 成本占评测成本的 90%+

**优化方案**:
1. **批量推理（Batch API）**:
   - OpenAI Batch API：50% 折扣，24 小时内完成
   - 适用场景：大规模离线评测（1000+ 样本）
   - 实现：新增 `BatchJudgeClient`，支持批量提交和结果轮询

2. **模型分层（Tiered Models）**:
   - 简单指标用 qwen-turbo（便宜 10 倍）
   - 复杂指标用 qwen-plus/qwen-max（准确但贵）
   - 实现：指标配置增加 `model_tier` 字段，支持每个指标独立配置模型

3. **缓存复用**:
   - 相同问题 + 相同回答 → 复用评测结果
   - 实现：基于 `(question_hash, answer_hash, metric_hash)` 的结果缓存
   - 预期节省：20-40%（取决于数据重复率）

**预期价值**:
- 降低评测成本 50-70%
- 支持大规模评测（10k+ 样本）
- 提升项目实用性（降低使用门槛）

**实现优先级**:
1. 批量推理（最高 ROI）
2. 模型分层（次高 ROI）
3. 缓存复用（锦上添花）

#### 1.3 实时评测进度推送（1 天）

**现状**: 前端需要轮询后端查询评测进度

**问题**: 
- 用户体验差（刷新延迟）
- 服务器压力大（无效轮询）

**优化方案**:
1. WebSocket 实时推送：
   ```python
   # 后端
   @router.websocket("/ws/evaluation/{task_id}")
   async def websocket_endpoint(websocket: WebSocket, task_id: int):
       await websocket.accept()
       while True:
           progress = get_task_progress(task_id)
           await websocket.send_json(progress)
           await asyncio.sleep(1)
   ```

2. Server-Sent Events (SSE)（更简单）：
   ```python
   @router.get("/evaluation/{task_id}/stream")
   async def stream_progress(task_id: int):
       async def event_generator():
           while True:
               yield f"data: {json.dumps(get_progress())}\n\n"
               await asyncio.sleep(1)
       return StreamingResponse(event_generator(), media_type="text/event-stream")
   ```

**推荐方案**: SSE（更轻量，浏览器原生支持）

### 🎨 优先级 5：差异化竞争力（影响项目亮点）

#### 5.1 评测结果对抗验证（3 天）

**概念**: 用另一个 LLM 验证第一个 LLM 的评测结果

**业界对标**: 
- DeepEval: 支持多 LLM 交叉验证
- RAGAS v1.0: 引入 Critique-based 验证

**实现方案**:
1. **对抗 Judge**:
   ```python
   primary_judge = OpenAIJudgeClient(qwen_plus)
   adversary_judge = OpenAIJudgeClient(gpt4)
   
   # 第一轮：primary_judge 评分
   score1 = await primary_judge.score(...)
   
   # 第二轮：adversary_judge 质疑
   critique = await adversary_judge.critique(score1, ...)
   
   # 第三轮：primary_judge 回应
   final_score = await primary_judge.respond(score1, critique, ...)
   ```

2. **分歧标记**:
   - 两个 Judge 分歧 > 0.3 → 标记为"需人工复核"
   - 降低 LLM Judge 误判率

**预期价值**:
- 提升评测可靠性（降低误判）
- 对标业界前沿（差异化能力）
